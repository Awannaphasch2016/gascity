Gas City on one public instance

A single Ubuntu machine in the default VPC is the entire factory: API, human approval, and the status page. The package declares a Gas City container. The notes that record the live box describe a Flask stand-in on the same port.

Verdict

The deployment is a one-tenant software factory demo, not a multi-tenant control plane. Scaling, in the scripts, means launching another copy of the same instance. Isolation is the instance boundary. There is no load balancer, no private subnet, no database service, and no Elastic IP.

Two topologies share one port

The repository contains a declared container stack and a separate account of what was actually left running. Both want TCP 7375. They cannot be the API at the same time.

Declared Compose stack

docker-compose.yml is what deploy-now.sh downloads onto the host and starts, and what deploy.sh expects an operator to upload to /opt/gascity.

  • gascity — image gastownhall/gascity:latest, command gc start, publish 7375.
  • telegram-bot — agent name you-agent.
  • telegram-bot-nordice — agent name nordice-agent.
  • miniapp — nginx:alpine, publish 8080:80.

deploy.sh also installs a systemd oneshot, gascity.service, whose start line is doppler run -- docker-compose up -d.

Recorded live Host processes

DEPLOYMENT_SUMMARY.md and FIX_GUIDE.md describe the host after the demo was brought up.

Approval path

Human-in-the-loop is a text protocol, not a Gas City primitive. An agent (or the test script) emits one line. Python decides who may answer. The dashboard is a browser poll of JSON files.

Who is allowed to approve

Policy lives in config/responsibilities.json. The checked-in file has placeholder Telegram ids of 0. The live notes say the host was loaded with real ids.

Quorum does not cross processes. Each bot keeps active_approvals in its own memory. When a message is fanned out, send_approval_request_sync builds a new approval id and sets approvers to only the recipient of that send. A deployment that needs two approvals can never reach required_count inside either process. The page’s “needs 2 approvals” line is static HTML in miniapp/index.html, not a count read from the JSON files.

Section titles the bot will persist are a fixed map: Hero Section, Features Section, Auth Form, Footer Section, Final Deployment. Any other title is logged and dropped, so the dashboard never moves.

The city the image would run

If the compose service actually stays up, gc start is the Gas City supervisor entry. It registers the city and runs the per-city controller: watch city.toml, reconcile sessions, evaluate orders. The mounted city is small.

city.tomlEffect
[city] name = "my-city"One city directory. Identity is fixed for the life of the controller.
[session] provider = "tmux"Agent sessions are tmux sessions inside the container.
[extmsg] enabled = trueExternal clients may register and open a reply stream.
[[agent]] deploy-agentOne worker. Provider claude. Prompt file tells it to emit APPROVAL_NEEDED lines. Working directory .

No rigs, no formulas, no orders, no pack imports. On the progressive capability ladder that is a city with sessions, tasks, and external messaging switched on. Graph orchestration — the reason the platform exists — has nothing to run.

What a full city keeps that this box does not

Bead store

Durable work. Tasks, mail, session records, and convoys are beads. The mock keeps queues in process memory, so a restart empties the factory’s inbox.

Orchestrator

Reconciles live sessions to city.toml on a ticker (default 30s) and on file change. One controller per city, locked with .gc/controller.lock.

Event bus

Append-only activity other humans and agents watch. The mini app does not subscribe to it. It polls five JSON files.

Wire contract

The bot was written against the real external-messaging registration call, then given a poll loop the real API does not serve. The mock was written against a third shape. The three do not meet.

Gas City supervisorTelegram botFlask mock
Register POST /v0/extmsg/clients with provider: llm-client. Returns client_id and a bearer. Same call. Header X-GC-Request: 1. Same path. Returns two random UUIDs. Ignores provider.
Receive replies GET /v0/extmsg/llm-client/{account}/{conversation}/subscribe SSE, Authorization: Bearer. Imports sseclient and never calls it. Polls POST /v0/extmsg/outbound every 3 seconds. Implements that poll. Drains and deletes the in-memory queue.
Send a turn POST /v0/extmsg/inbound fields provider, account_id, conversation_id, content. Sends those fields. Reads client_id and message. A bot payload therefore has an empty body.
Health GET /v0/readiness Debugging notes also mention /health. GET /health → {"status":"ok","clients":N}.

DEBUGGING_GUIDE.md tells an operator to grep bot logs for Received event from Gas City. The current poll_for_messages loop never writes that line. A green grep is not available as a health check.

Multi-tenant, in the deployment summary, means another instance per tenant. At the live size that is another m7i.xlarge. A re-run of the scripts, which still default to t3.medium, would launch the small size instead. Nothing in the security group, the city name, or the Docker network carves tenants inside one host.

Trust boundary

Exposed Data plane

SSH, the API, and the status page accept the whole internet. The API has no TLS terminator in front of it. Ports 80 and 443 are authorized and unused, so they read as a future HTTPS plan that was never wired.

The mock’s register call issues a token and the poll checks it. The inbound route does not. Anyone who can reach :7375 can enqueue APPROVAL_NEEDED lines.

User-data Secret handling

deploy.sh embeds a Doppler service token in user-data. deploy-now.sh embeds Telegram bot tokens in the same channel, then writes them to /opt/gascity/.env. User-data remains readable to principals who can describe instance attributes.

The live instance has no IAM instance profile. Instance metadata tokens are optional, so IMDSv1 is still accepted. AWS credentials used to launch the box stay on the operator workstation (and in Doppler), and the guest can still be handed a long-lived Doppler token through user-data.

The compose network is the only private path: bots use http://gascity:7375. Publishing 7375:7375 punches that path out to the security group. A city process that followed the product default would listen on localhost inside the container; the publish mapping is what makes it a public API.

Findings

  1. The recorded host is the mock, and the package still boots the product. Operators following FIX_GUIDE.md bind Flask to 7375. Operators following deploy-now.sh bind gc start to 7375. The debugging guide, the summary, and the compose file describe different machines. Pick one listener before treating the instance as a city.
  2. The bot, the mock, and the supervisor speak three dialects. Registration matches. Replies do not: the product is SSE, the bot polls /v0/extmsg/outbound, and the mock is the only thing that implements that poll. Inbound field names also differ, so a grant posted by the bot is invisible to the mock’s parser.
  3. Two-person deployment approval cannot complete. Quorum state is per process and per recipient. deployment_approval asks for two yes-votes and each button only has one eligible voter. A reject completes the record; a pair of approves does not.
  4. The public surface is larger than the demo. Five ports from 0.0.0.0/0, cleartext API and dashboard, inbound approval injection on the mock, and secrets in user-data. SSH on the same group is the break-glass and the front door.
  5. Durability is the root volume plus a Docker named volume, with no snapshot. Approval state that matters to a human is a handful of JSON files. City state, if the real process is ever the one on 7375, lives in gascity-data on that same disk. Replacing the instance replaces the factory.
  6. The running host is an m7i.xlarge. The scripts still launch a t3.medium. Live shape: 4 vCPU, 16 GiB, up to 12.5 Gbit, launched 24 Sep 2026 in ap-southeast-1c. That is enough machine for a controller and a small agent session. It is 4 cores and 16 GiB, which is m7i.xlarge. m7i.large is 2 vCPU and 8 GiB. Eight cores and 16 GiB would be a c7i.2xlarge. Eight cores in the M7i line is m7i.2xlarge at 32 GiB. On-demand Linux in Singapore is $0.252 per hour, about $184 per month before the 30 GiB gp3 disk. The package’s ~$33 figure is the old t3.medium estimate. Re-running deploy.sh without INSTANCE_TYPE would create a new small instance beside this one.
  7. “One city per tenant” is the whole tenancy model. That is a legitimate isolation boundary. It is not a control plane: no shared identity, no per-tenant network, no central ledger. Cost scales with one m7i.xlarge per tenant, about $184 of compute each, plus disk and transfer.
  8. To run Gas City here, the mock has to leave port 7375. The city directory and [extmsg] enabled = true are already the right switch. The bot would subscribe to the SSE stream documented in docs/guides/connected-clients.md, keep quorum in one place both bots can see, and stop publishing 7375 to the world — or put TLS and an allowlist in front of it. Formulas, rigs, and a durable bead backend are what turn this host from an approval toy into an orchestrator.
